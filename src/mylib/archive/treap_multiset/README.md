# TreapMultiSet の採用見送り

挿入する値を事前登録せずに、重複込みの順位と範囲内個数を求める多重集合を試作した。同じ値を 1 ノードにまとめ、部分木ごとに出現回数の合計を保持する。

通常利用では既存の `BucketMultiSet` と `FenwickTreeSparseMultiset` を使い、Treap の採用は見送った。広い値域では、保持数が増え続ける場合も直近 1,024 件だけを保持する場合も Bucket の方が速かった。値が 1,024 種類に限られる場合、Treap は Bucket より速かったが、候補値を事前登録できる条件では Fenwick Sparse が最速だった。候補値を事前登録できず、同じ値が多く、保持する総個数が大きい問題では Treap を再検討できる。

## 計測結果

整数 100 万件を使い、Intel Core i5-12400 の 1 論理 CPU に固定して計測した。Rust 1.97.1 の最適化ビルドで各ケースを 7 回実行し、中央値を採用した。Fenwick の座標圧縮にかかった時間を含む。全ケースで 3 実装の問い合わせ結果が一致した。

| 操作列 | Treap (ms) | Fenwick Sparse (ms) | Bucket (ms) |
|---|---:|---:|---:|
| 広い値域、追加ごとに中央値 | 1,708.79 | 500.39 | 519.17 |
| 1,024 種類、追加ごとに中央値 | 88.06 | 51.52 | 571.61 |
| 広い値域、直近 1,024 件の中央値 | 275.92 | 728.21 | 96.35 |
| 1,024 種類、追加ごとに範囲内個数 | 138.29 | 71.29 | 782.87 |
